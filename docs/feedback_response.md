# 수강신청 DB 설계 피드백 반영 내용

## 1. TBL_ENROLLMENT

- `lessonEndDate` 컬럼을 추가했습니다.
- 수업 시작일보다 종료일이 빠르게 저장되지 않도록 `CK_TBL_ENROLLMENT_DATE_RANGE` 제약조건을 추가했습니다.
- 강사별 수업 기간 조회를 고려해 `IX_TBL_ENROLLMENT_TUTOR_TIME` 인덱스에 `lessonEndDate`를 포함했습니다.

## 2. 요일 저장 방식 검토

- 기존처럼 `TBL_ENROLLMENT_WEEKDAY`를 유지했습니다.
- 이유는 한 신청에 월수금, 화목처럼 여러 요일 조합이 들어갈 수 있고, 요일 기준 검색과 중복 방지를 명확하게 처리할 수 있기 때문입니다.
- 단점은 신청 1건에 요일 여러 건이 생겨 JOIN이 필요하고, 요일 변경 시 연결 데이터를 함께 수정해야 한다는 점입니다.
- 반대로 `TBL_ENROLLMENT`에 요일 문자열이나 여러 컬럼으로 저장하면 조회는 단순하지만, 요일 조합 검색과 데이터 정합성 관리가 어려워집니다.

## 3. TBL_CLASS_SCHEDULE

- 기존 설계를 유지했습니다.
- 실제 수업일, 회차, 시작/종료시간, 수업 상태를 일자별로 관리할 수 있어 출결, 수업 URL, 취소/변경 이력 확장에 적합합니다.

## 4. 검증 보완

- 더미데이터에 수업 종료일을 추가했습니다.
- `lessonEndDate`가 해당 신청의 마지막 `TBL_CLASS_SCHEDULE.classDate`와 같은지 확인하는 검증 쿼리를 추가했습니다.
